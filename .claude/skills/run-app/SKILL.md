# Wildcard を実際に動かす

テストは「落ちない」ことまでしか見ない。卓が潰れて消える、カードが読めない、
手番が進まない——この種の不具合はブラウザで動かさないと分からない。

## 1. 開発サーバーを立てる

```bash
cd packages/client && npx vite --port 5173 --strictPort > /tmp/vite.log 2>&1 &
sleep 4 && curl -s -o /dev/null -w "%{http_code}\n" http://localhost:5173/
```

`200` が返れば起動している。

> **注意**: バックグラウンド実行のあとシェルの作業ディレクトリが戻る。
> 続きのコマンドでは必ず `cd packages/client` をやり直すこと。

## 2. 実際に1ハンド遊ばせる

```bash
cd packages/client && node scripts/drive.mjs
```

セットアップ画面 → CPU相手に着席 → ゲーム開始 → ソロで1ハンドを
終えるまで遊びきり、`packages/client/shots-solo/` にスクリーンショットを残す。
ホットシートは削除済み。`drive.mjs` はソロの検証を呼び出す。

**撮った画像は必ず Read で開いて目で見ること。** 真っ暗なら起動に失敗している。

出力で特に見る行:

| 行 | 意味 |
|---|---|
| `自分の見えるカード: 2 枚` | 自分の手札が見えている |
| `CPU の裏向きカード` | 他人の手札が伏せられている |
| `[browser error]` / `[page error]` | コンソールエラー。出たら直す |
| `--- ショーダウン ---` | 1ハンド通しで遊べている |

環境変数で挙動を変えられる。

- `WILDCARD_URL` … 接続先（既定 `http://localhost:5173/`）
- `WILDCARD_SHOTS` … スクリーンショットの出力先（既定 `shots/`）
- `WILDCARD_BROWSER` … 使う Chromium の実行ファイルパス

## 2b. 役の順位表を見る

```bash
cd packages/client && node scripts/drive-rules.mjs
```

ルールを切り替えながら順位表を開き、各役の**例の札を aria-label で読み上げて**
出し、`shots/rules-N.png` を残す。例の生成はエンジン側でテストしてあるが、
「読めるか」は画面を見ないと分からない（→ docs/variants.md 段階4）。

`WILDCARD_VARIANTS` に `,` 区切りで**画面に出ている名前のまま**渡す
（`ショートデッキ（6+）` のように括弧まで含める）。

## 2c. ルールの編集画面を触る

```bash
cd packages/client && node scripts/drive-editor.mjs
```

プリセットを元に自作ルールを作り（スートを抜く・フロップ6枚・独自役を足す）、
矛盾の表示を確かめ、保存して **そのまま遊ぶところまで** 通す。
ここは Wildcard の主役なので、「保存できた」では確認にならない。

出力で特に見る行:

| 行 | 意味 |
|---|---|
| `いちばん下での例: (出ない — 上の役に先に当たる)` | 役の強さが例示に効いている |
| `強さを2つ上げた → 例: ...` | 上げると成立する。ここが空なら例示が壊れている |
| `わざと壊す（手札10枚） --- 矛盾 1件` | 検算が効いている |
| `戻ってきたタブ: ソロ` | 編集から戻ってもモードが保たれている |
| `配られた場: ... （6枚）` | 作った構造で実際に配られている |
| `クラブ: 0枚` | 抜いたスートが本当に出てこない |

## 2d. ランイットトゥワイスを見る

```bash
cd packages/client && node scripts/drive-runs.mjs
```

カジュアル卓でわざとオールインし、「2本走るか」を聞かれ、同意して
**2本のボードが並ぶ**ところまで通す。CPU は断らない。

| 行 | 意味 |
|---|---|
| `聞かれた: はい` | オールインまで行けている（いいえなら CPU が降りた） |
| `ボード 2本` | 走った本数 |
| `内訳 2件` | 走りごとの勝敗が出ている |
| `重複 0枚` | 同じ札が2本のボードに出ていない |

## 2e. 賭け方の制度を見る

```bash
cd packages/client && node scripts/drive-betting.mjs
```

リミット／ポットリミット／ストラドル／オールイン禁止の4つを順に開く。
**画面が自前で上限を計算していないこと**を確かめるのが目的。

| 行 | 意味 |
|---|---|
| `ボタン: ... / レイズ 40` | フィックスリミットは額込みのボタン（スライダーが出ない） |
| `ポット 30 / レイズ上限 70` | ポットリミットの上限が `currentBet + pot + toCall` |
| `クイック: ... / 上限` | 上限が手持ち全部でないときは「オールイン」と書かない |
| `ストラドルを出せた: 自分の額 40` | BB の左隣に回ったハンドで倍の賭け金が出ている |

ストラドルは席順が回ってこないと出せないので、数ハンド進めてから判定している。

## 3. 終わったらサーバーを止める

`pkill` ではこの環境の Vite を落としきれないことがある。PowerShell で確実に止める。

```powershell
Get-CimInstance Win32_Process -Filter "Name='node.exe'" |
  Where-Object { $_.CommandLine -like '*5173*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
```

## ブラウザの用意

初回だけ必要。

```bash
npx playwright install chromium
```

**Playwright のバージョンは 1.49.1 に固定してある。** この環境の Node は 18.15.0 で、
1.5x 以降は Node 20 以上を要求して動かない。上げるなら Node ごと上げること。

Edge を `channel: 'msedge'` で使う手は試したが、起動直後に接続が切れて使えなかった。
`npx playwright install chromium` で入る専用ビルドを使うこと。

## つまずいたときの勘所

**卓が消える / Playwright が `hidden` と言う**
`.table-area` のサイズは必ず「幅起点 + `aspect-ratio`」で決める。高さが flex で
後から決まる `.table-wrap` に対して `height: 100%` を指定すると解決できず、
要素が潰れて卓ごと消える。一度これで踏んでいる。

**ボタンが見つからない**
`getByRole('button', { name: 'レイズ' })` は「〜にレイズ」にも一致する。
`exact: true` を付けるか正規表現で先頭を縛る。
