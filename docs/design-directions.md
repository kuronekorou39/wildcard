# Wildcard デザインの方向性

2026-10-20。既存のアプリを確認したうえでの初回提案。実際のアプリ画面の変更前に、3方向 × トップ・ゲーム・設定の9画面を比較する。

## 現在の構成と、見直すポイント

- React + Vite。トップ兼セットアップ、3モード共通の卓表示、ルール編集が主要画面。
- オンライン、ソロ、ホットシートを利用できる。「身内で、自分たちが決めたルールで遊ぶ」が中心。
- 現在は深緑のフェルト、金、木目色が中心。新しいキャラクターの赤・黒・白とブランドの印象が離れている。
- トップには参加方法、プレイヤー名、チップ、ブラインド、ルール、説明が同居している。最初は「どう遊ぶか」を選び、その後に卓の設定へ進む構成を提案する。
- ルール編集はデッキ・配り方・ベット・役・卓の作法・検証・共有が縦に続く。分類ナビゲーションと設定結果の要約で見通しをよくする。

## キャラクターから作る基本設計

元画像はプロジェクト直下の `Gemini_Generated_Image_m4dxmam4dxmam4dx_01_clean.png`。485 × 723 px、透過PNG。プレビューにはこの画像をそのまま使用している。

- ブランドの赤：画像中の主要な赤 `#C22B31`。主操作、ロゴ、短い強調に使う。
- 墨黒：ベスト・帽子・線画につながる色。文字、輪郭、暗い背景に使う。
- 白〜生成り：シャツとカードにつながる色。カード、キャラクターの背景、明るい画面に使う。
- 全身：トップ画面の案内役。シルエットが見える余白を確保する。
- 顔：ヘッダーや小さな案内に使う。今回の表示は元画像の表示範囲を切り取った仮案。
- 小サイズの正式なアイコン：採用案を決めた後に、角・目・鼻先・帽子を残して線を整理する。ファビコンを単純な全身画像の縮小にはしない。
- 対局中：キャラクターは小さく扱い、カード、手番、ポット、行動の読み取りを優先する。

## Velvet Club

赤いドラゴンが迎える、小さなプライベートクラブ。キャラクターのベストとトップハットを最も自然に生かす方向。

**配色**：赤 `#C22B31` / 墨黒 `#191719` / 生成り `#F3EADF` / 淡いサンド `#DBC5A6`。

**トップ**：左にコピーと入口、右に全身。生成りのアーチが黒い服と輪郭を引き立てる。下段に3つの遊び方を並べる。

**ゲーム**：チャコールの楕円卓。白いカード、明るい手番枠、赤いレイズボタン。広い画面では右に進行履歴とルールの確認を置く。

**設定**：左に分類、中央に編集、右に設定の要約と保存。「役の強さ」を編集しながら成立する手の例を見る。

**合う印象**：落ち着き、少し洒落た雰囲気、長く使えるブランド。濃い赤の大面積使用や強い金属光沢は抑え、重くしすぎない。

## Paper Lounge

カードと紙の温かさを感じる、仲間の集まる明るい部屋。ホームゲームの親しみやすさを最も強く出す方向。

**配色**：赤 `#C22B31` / 生成り `#F3EFE6` / 墨色 `#292525` / 紙の影 `#E9E2D6`。

**トップ**：左のキャラクターと右の呼びかけ。その下にオンライン、ソロ、ホットシートを丸みのある選択肢として置く。

**ゲーム**：明るいベージュの卓と白いカード。履歴を常設せず卓を中央に広く取り、操作を丸みのある下部パネルに集める。

**設定**：上に分類、下に読みやすい編集フォーム。右の要約にはキャラクターの顔を添える。狭い画面では編集の次に要約が続く。

**合う印象**：親しみやすさ、初見の入りやすさ、設定の読みやすさ。夜の対局向けには、採用後に同じ構成の暗いテーマを検討できる。

## Wild Ink

キャラクターの強い線を、ポスターやカード箱のようなグラフィックへ広げる方向。

**配色**：赤 `#C22B31` / インク色 `#20211F` / 紙色 `#EDEDE6` / 卓の色 `#D4D4C6`。

**トップ**：大きな英字、左右分割、赤いキャラクター枠。太い罫線と少し傾いた紙面で印象を作る。

**ゲーム**：角を丸めた長方形の卓。左にコンパクトな履歴、中央にカード、下に大きな操作。直線と輪郭で情報を区切る。

**設定**：カテゴリ、編集、要約を罫線で連結した編集盤。役の順序を組み替える操作を前面に出す。

**合う印象**：独自性、遊び心、カスタムルール。強い輪郭はトップ中心に使い、対局中は装飾密度を抑える。

## 共通の画面設計

1. トップ：部屋を作る / コードで参加 / ソロ / ホットシート / 自作ルールへの入口。
2. ゲーム：ルールと進行役 → 卓・場札・ポット → 自分の手札 → 行動。対局中の情報はこの順序で整理する。
3. 設定：卓の基本 / デッキ / 配り方 / 役の強さ / ベット / 卓の作法。結果の要約と「このルールで試す」を近くに置く。

トップ・ゲーム・設定の切り替えは比較用ナビゲーション。実装時の参加手続きや対局中の離脱確認などの画面遷移を確定するものではない。

## 実装に進むときの条件

- 既存のゲームエンジン・通信・手札の秘匿を維持し、画面層を更新する。
- 色だけで手番、エラー、フォールドを区別しない。文言、形、輪郭を併用する。
- 文字と背景のコントラストを実測する。カードの赤とブランドの赤は役割を分ける。
- ホットシートの手渡し画面は、他人の手札をDOMに残さない現行の仕組みを維持する。
- 最大10人、オマハの手札4枚、フロップ6枚のルールの場札8枚、複数ボード、観戦状態、長い名前を別途設計・確認する。今回の比較は4人・標準ルールのサンプル。
- 卓の開始条件と保存するルール定義は、見た目を統一しても既存のデータ上の区別を維持する。
- ルール保存・読み込み・共有、カスタム役作成、エラー表示などは、採用案で詳細画面を詰める。今回の案はそれらを削除する提案ではない。
- モバイルでは縦長の卓、下部の行動ボタン、折り返す設定ナビゲーションを使う。

## 今回の成果物と確認

`output/design-review/wildcard-directions.html` は初回提案の比較用プレビュー。元画像を埋め込み、3案と9画面を切り替えられる。初回提案時点ではReactアプリを変更していない。

画面切り替え、設定分類、役の順序変更、レイズ額変更は表示確認用に操作可能。ルールの検証・保存、通信、実際の対局はエンジンと接続していない。

既存トップと提案画面をブラウザで表示して確認。デスクトップとスマートフォン幅で、画像の表示、はみ出し、主要操作を確認する。

第一候補は **Velvet Club**。キャラクターの服装とサイト全体の印象が自然につながる。親しみやすさを最優先するなら **Paper Lounge**、カスタムルールの楽しさを強く打ち出すなら **Wild Ink**。

## 続き：Velvet Club を実画面へ反映

「続き」の依頼を受け、第一候補の Velvet Club を軸に実装した。

- `Brand.tsx` で全身と顔マークを共通化。元画像は `public/brand/dragon.png` に変更せず配置し、GitHub Pages のベースパスにも対応。
- トップはキャラクター、参加への入口、3つの遊び方、卓の設定の順に整理。「コードで参加」は参加フォームへ直接つながる。
- 卓は墨色のフェルト、生成りのカード、赤い主操作に統一。席の座標と手札の秘匿は既存の実装を利用。
- 多人数の狭い卓では縦方向の余白を増やし、自分の席と隣席を分離。場札8枚は狭い画面で折り返す。
- ルール編集は分類ナビ、編集欄、検証・保存欄に分けた。分類は同一画面内の移動なので、各編集部品の状態を保持する。狭い画面では保存操作を下部に置く。
- 保存・検証・役の例・共有・対局は実際のエンジンに接続したまま。初回プレビューとは異なり、実際にルールを作って遊べる。
- 画面を移るとスクロールを先頭へ戻し、長い設定画面の途中から卓へ入っても操作が見つかるようにした。

検証は既存テスト、ビルド、実ブラウザでのホットシート1ハンド、カスタムルール編集から対局、複数ボード、各種ベット制度を実施。デスクトップとスマートフォンで、画像の読み込み・はみ出し・席の重なりも確認した。

## ゲーム画面：卓の拡大とカードの選択

色調はそのまま、対局中の読みやすさを優先して更新した。

- PCの卓の最大幅を820pxから1120pxへ拡大。場札は最大66px幅、自分の手札は62px幅にした。画面の高さも考慮し、卓の余白を調整する。
- 自分の手札は卓の手前に独立させ、通常のレイアウト内に配置する。手札が増えても操作欄と重ならず、スマートフォンのオマハ4枚も横に並ぶ。
- 小さい画面の多人数卓は縦長にし、必要に応じて場札を折り返す。相手の席を優先してカードを隠すことはしない。
- ゲーム画面の「カードのデザイン」から表面3種類（クラシック／ラージインデックス／4カラー）、裏面3種類（ドラゴン／ダイヤモンド／モノグラム）を独立して選ぶ。固定のサンプル札でプレビューする。
- 選択は即時反映し、ブラウザに保存する。他の参加者の表示は変更しない。保存できない環境でも、そのセッションでは選択した表示を使える。
- 4カラーはスペードが墨色、ハートが赤、クラブが緑、ダイヤが青。数字とスート記号を全スタイルで保持する。ジョーカーも専用の表示を保持する。
- ドラゴンの裏面は元画像の顔を使用。CSSだけで作る他のカード柄も含め、ゲームの手札データや判定は変更しない。

実装は `cardAppearance.tsx`、`CardAppearancePicker.tsx`、`PlayingCard.tsx`、`PokerTable.tsx` と `cards.css`／`game.css`。`scripts/drive-appearance.mjs` で9通りの組み合わせ、保存・復元、保存拒否時の表示、Escapeとフォーカス復帰、手札の秘匿、320〜1280pxの34画面パターンを確認した。ホットシート1ハンドと2本のボードも実ブラウザで確認。単体テストはクライアント112件・エンジン448件が通過した。

## ゲーム画面：画面内に収まる10人卓

2026-10-21。719px以下で操作欄が画面外へ押し出される問題に対応し、ゲーム画面を利用できる高さに合わせる構成へ変更した。

- `100dvh` の画面を卓・手札・操作欄に配分。通常の対局ではページをスクロールしない。レイズ額の調整も操作欄の高さを変えず、その上に開く。
- ヘッダーをなくし、左上に戻る、右上に情報ボタンを配置。キャラクターとロゴはフェルト中央に控えめに表示する。高さが足りない画面ではカードを優先する。
- 情報パネルを「テーブル」「ルール」「見た目」に分け、ルールの順位表やカード設定をパネル内に収める。長い内容だけが内部でスクロールし、閉じるボタンは常に見える。Escape、フォーカス復帰、タブの矢印キー操作にも対応。
- 縦長の画面では相手を左右と上部へ、横長の画面では卓を囲むように配置。相手の枠と持ちチップを小さくし、各席にアイコン用の丸い領域を確保した。現在は名前の頭文字、CPUと初期プレイヤー名では番号を表示する。
- 自分の手札は操作欄のすぐ上に横並びで配置。320pxの画面でもオマハ4枚を同じ列に収める。
- ディーラー、SB、BBをフェルト上のボタンとして席の内側へ配置。ヘッズアップのD兼SB、フォールド後、次のハンドへの移動もエンジンの席順に従う。
- ソロのCPUを最大9人に増やし、本人を含めた10人卓を試せるようにした。
- 「見た目」でラウンドレクト、オーバル、パースの3形状を切り替え、ブラウザに保存する。カードの表面・裏面も同じパネルから変更できる。
- ハンド終了時は配当と次のハンドの操作を下部に表示し、各人の役、複数ボードの内訳、公開する手札などは「結果の詳細」で確認する。

`scripts/drive-viewport.mjs` は320×568〜1280×900、719pxと720px、横向き844×390を含む85画面状態を確認する。10人卓、オマハ、場札8枚、レイズ、情報パネル、ソロCPU9人を実際に操作し、ページのはみ出し、席・場札・ポジションボタンの重なり、操作欄の到達性、手札の横並びを検証する。既存のカード9通りと34画面、ホットシート1ハンド、CPU9人との1ハンド、2本のボード、4種類のベット制度も実ブラウザで確認した。
