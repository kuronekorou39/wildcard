- このリポジトリは GitHub Pages でゲーム・ルール・表示を確認できる検証版として仕上げる。

## 2026-10-30 の課題と対応結果

### 1. アンティはあるか

**実装済み：全員アンティ。** 調査時点では設定・徴収がなかったため、準備画面に「アンティ / 人」を追加した。
SB/BB と同じ卓の掛け金設定で、Variant のルール定義とは分ける。既定0で従来の挙動を保つ。

- 参加者全員から指定額を徴収し、最初から中央へ入れる。SB/BB はプレイヤーの前に残す。
- 3人・アンティ5・SB10/BB20なら中央表示は `15（+30）`。アンティはコール済み額に含めない。
- チップが足りない人は残額だけ支払い、オールインとしてそのハンドに参加する。徴収前に配牌対象を確定する。
- 離席者・チップ0の席は徴収対象外。履歴にも「アンティ」と中央への移動を記録する。
- 旧保存データの未指定値は0。ソロ・P2P・サーバー卓に共通の設定。

少額スタック、全員がアンティでオールイン、離席者、旧データ、各手順のチップ総量、サーバー復元をテスト済み。
**BBアンティは持ち越し。** 人数による額と、BBとの支払優先順位を決めてから追加する。

実装：[ゲーム進行](../packages/engine/src/game/reduce.ts)、[表示用のチップ管理](../packages/table/src/runtime.ts)、[検証](../packages/engine/test/ante.test.ts)。

### 2. CPU 戦を離れると戻れないのに、確認画面では戻れそうに見える

**文言を修正済み。** ソロ・P2P主催者は「ゲームを終了しますか？」、
「終了して設定へ戻る」「プレイを続ける」と表示する。サーバー卓・P2P参加者は退出として扱う。
サーバー卓は、保存期間内に同じブラウザで招待リンクを開くと同じ席へ戻れることを説明する。

**ソロの中断・再開は今回の範囲外。** 終了すると対局状態を破棄する挙動は変えていない。
将来は手番、残り時間、演出、CPUの個性も保存し、中断中に時間切れを進めない仕様が必要。

実装：[共通確認画面](../packages/client/src/components/TableView.tsx)、[ソロ](../packages/client/src/modes/SoloTable.tsx)、[サーバー卓](../packages/client/src/modes/ServerTable.tsx)。

### 3. プレイヤーの位置は維持して、テーブルの背景だけ大きくしたい

**実装済み。** 卓の情報 → 見た目 →「テーブル背景の広さ」で標準／ワイドを選ぶ。既定ワイド。
フェルト・縁・影の SVG だけを拡大し、画面外の装飾はゲーム画面でクリップする。
席・手札・場札・ベット・ディーラーボタンの座標と当たり判定は変えない。端末内に選択を保存する。

3形状の切替前後で席・中央の座標が変わらないことをブラウザで検証した。
スマホ縦横／PC、2・6・10人の通常・レイズ・結果画面も確認済み。

実装：[卓のCSS](../packages/client/src/game.css)、[表示設定](../packages/client/src/tableAppearance.ts)。

### 4. レイズの比率プリセットをキリのよい金額にしたい

**実装済み。** 比率候補だけを、BBの半分以下で最大の1・2・5系列の単位に丸める（最小1）。
BB20なら10刻みで233→230、BB50なら20刻み。対象はレイズ先の総額。

- 比率はコール後のポットに対する上乗せ。丸めで変化した候補には「約」を付ける。
- 最小・上限・オールインは正確な額のまま。手動の＋／−と直接入力は1刻みを維持。
- 昇順・重複排除を保ち、通常の比率候補が丸めでオールインになる場合は除外する。
- プリセット選択だけでは送信せず、確定操作を別に行う。

実装：[レイズ候補](../packages/client/src/components/ActionBar.tsx)、[境界値テスト](../packages/client/test/quickAmounts.test.ts)。

### 5. オンラインの部屋がずっと残っているように見える

**状態・期限表示を追加済み。保存方針は変更なし。**
サーバー卓は作成から7日間保存（`TABLE_TTL_HOURS=168`）。アクセスによる延長はしない。
全員が退出しても即削除しない。主催者の「卓を終了」は次の開催・参加を止め、記録は期限まで残す。
期限をまたぐハンドは精算後の削除を優先する猶予がある。P2Pの一時的な卓はこの保存方式とは別。

卓情報に待機中／開催中／終了・記録のみと保存期限を表示する。
404・410・期限切れ通知で消滅が確認できた場合は再接続を止め、端末内の参加情報を削除できる。
ネットワーク障害で勝手に資格情報を消さず、削除前には確認を出す。サーバー上の既存卓を削除する操作ではない。

**保存期間の短縮・無人時間による終了は持ち越し。** AWS版のクラブ自体の寿命と開催・履歴の寿命も分ける。

実装：[保存設定](../packages/server/wrangler.jsonc)、[再接続](../packages/client/src/transport/server.ts)、[卓情報](../packages/client/src/modes/ServerTable.tsx)。

### 6. ハートの9だけ3枚などの個別枚数と、デッキ全体の表示

**実装済み。** 既存の `deck.overrides` を編集画面につないだ。
デッキ →「カードごとの枚数」で種類を選び、その枚数を押して編集する。
標準デッキの9♥だけ3枚なら合計54枚。0で除外、「共通の枚数に戻す」で上書きを解除する。
共通枚数を変えても個別指定を優先する。スート／ランクを外すと、該当する個別指定も除く。

カード構成は編集画面とルール詳細で確認できる。

1. 一覧：1枚ずつ重ねずに並べる。同種の札も実数だけ表示。
2. 重ね：半分ずつ重ねて並べ、行の幅で折り返す。
3. 扇形：行の幅に収まる弧。横スクロールは出さない。

どの表示もスートごと（ジョーカーは別）に行を分ける（2026-10-31 変更）。

1ページ52枚。1000枚は20ページに分け、長い一覧だけを内部でスクロールする。
上限超過中はカード生成を止め、保存も不可。表示は構成一覧であり、対局中の秘密の山札順序ではない。
必要な配牌枚数の不足は既存のルール検証で確認する。

**重複札に伴う不具合も修正。**
CPUの未知の山札から既知の札を「枚数分だけ」引くようにした。
勝ち札の強調は、同じ値の全カードではなく実際の位置を選び、オマハの手札2枚・場3枚も守る。
複製札を含む勝率・使用札の回帰テストと、54枚の保存・再読込・対局開始、1000枚表示を検証済み。

実装：[個別枚数](../packages/client/src/components/editor/DeckCards.tsx)、[構成表示](../packages/client/src/components/DeckContents.tsx)、[CPUの推定](../packages/engine/src/ai/equity.ts)、[使用札](../packages/client/src/showdownSelection.ts)。

### 7. CPU ごとにスタイルをばらけさせたい

**実装済み。** 既定を「混在」にし、慎重・標準・強気を人数の差が1以内になるよう割り当てる。
割り当ては卓の開始時に固定し、ハンドや手番ごとに変えない。従来の全員共通設定も残す。
各CPUのスタイルは卓情報に表示する。9人なら3人ずつ。
同じ割当シードで同じ構成になること、人数1〜9で偏らないことをテストした。

既存の攻撃性を使う実装。タイト／ルースと攻撃性を分ける詳細な個性は持ち越し。

実装：[割当](../packages/client/src/cpuStyles.ts)、[ソロ](../packages/client/src/modes/SoloTable.tsx)。
