# 配牌の公正さ

この文書は、現在のプレビューの **P2P 対戦** を対象とする。
サーバー版は Web Crypto の乱数列で配牌し、視点ごとに秘匿して配信する。
以下の P2P 用の配牌検証はサーバー版には適用しない
（[architecture.md](./architecture.md)、[server-preview.md](./server-preview.md) を参照）。

P2P 対戦では、誰かの端末が配る役（host）になる。その端末は全員の
ホールカードを計算できる立場にある。この文書は、**そのうえで何を保証でき、
何を保証できないのか**をはっきりさせるためのもの。

## 保証できないこと

**host が手札を見てしまうこと自体は防げない。**

host はエンジンを回している端末なので、全員の配牌がメモリ上にある。これを
塞ぐには、カードを全員で多重に暗号化して誰も単独では復号できないようにする
（メンタルポーカー）か、プレイヤーではない第三者のサーバーを立てるしかない。
どちらも今のところやっていない。

緩和策として用意してあるのは次の2つで、どちらも「防ぐ」ものではない。

- 進行役が誰かを画面に常時表示する
- 部屋を作るとき「自分も席に着く」を外せる。席を持たない進行役の画面は
  `project(state, null)` を見るので、**誰のホールカードも表示されない**。
  遊ばない人が1人いるなら、その人が部屋を作るのが一番安全

## 保証できること

防げるのは、**見た結果に合わせて配牌を操作すること**のほう。

| 不正 | 内容 | 塞げるか |
|---|---|---|
| 配り直し | 配って自分の手を見て、気に入らなければ配り直す | ✅ |
| seed 漁り | 事前に何千通りも seed を試し、自分に良い手が来るものを選ぶ | ✅ |
| 覗き見 | 進行中に全員の手札を見る | ❌ |

ただしこれも**証明ではなく、後から検証できる記録を残すこと**である。
不正ができなくなるのではなく、やったら必ずバレる状態になる。

## 手順

ハッシュのコミットだけでは**配り直ししか塞げない**。配る前に好きなだけ
探索できてしまうからである。両方塞ぐには全員が乱数を持ち寄る必要がある。

```
1. host が秘密の乱数 R を作り、commit = SHA-256(R) を全員に配る
   → この時点で R は固定される（ハッシュから R は逆算できない）

2. 各 guest が自分の乱数 Nᵢ を host に送る
   → host は R を固定した後に Nᵢ を受け取る。Nᵢ を知らずに R を決めている

3. host が seed = SHA-256(R ‖ N₁ ‖ N₂ ‖ …) を計算して配る
   → R だけでも Nᵢ だけでも seed を決められない。host は結果を狙えない

4. セッション終了後、host が R を公開する

5. 各自が手元で検証する
   - SHA-256(R) が手順1のコミットと一致するか
   - SHA-256(R ‖ 受け取った全 Nᵢ) が使われた seed と一致するか
   - 自分の乱数がその一覧に入っているか
```

`N` の並び順で seed が変わると host が並べ替えで結果を選べてしまうので、
`playerId` で並べ替えて順序を固定している（`canonicalNonces`）。

## なぜ検証が成立するのか

**エンジンが乱数を持たず、seed を外から受ける設計にしてあるから**（原則1）。

同じ seed からは必ず同じ配牌が再現される。だから公開された `R` と乱数一覧から
seed を計算し直し、そのハンドを手元のエンジンで回して、実際に見えたカードと
突き合わせられる。乱数をエンジンの内部に持たせていたら、この検証はできない。

## 抜け道とその扱い

| 抜け道 | 扱い |
|---|---|
| host が R を公開しない | 検証画面に「未公開」の件数が出る。公開を拒むこと自体が見える |
| host が別の R を公開する | コミットと一致しないので即座にばれる（`commit-mismatch`） |
| host が誰かの乱数を外して配る | 外された本人の検証が落ちる（`nonce-missing`） |
| host が乱数を集めてから配らずに中断し、やり直す | 中断も記録して公開対象にする。乱数が揃っていたのに中断していれば `suspicious-abort` として出る。繰り返せば件数に出る |

いずれも**事後に分かる**だけで、その場で止められるわけではない。
身内で遊ぶ前提なので、バレることが抑止になるという想定に立っている。

## 公開のタイミング

R を公開すると、その seed から**全員のホールカードが再現できる**（降りた手も
含めて）。対局中に公開すると手の内が割れるので、**セッション終了後にまとめて
公開する**運用にしている。検証は後からでもできる。

## 実装の場所

| ファイル | 内容 |
|---|---|
| `packages/engine/src/fair/commit.ts` | 乱数、ハッシュ、seed の導出 |
| `packages/engine/src/fair/verify.ts` | 記録の検証と集計 |
| `packages/client/src/net/protocol.ts` | `DEAL_COMMIT` / `DEAL_NONCE` / `DEAL_SEED` / `DEAL_ABORT` / `DEAL_REVEAL` |
| `packages/client/src/transport/host.ts` | コミット → 乱数収集 → seed 決定 → 配る |
| `packages/client/src/transport/guest.ts` | 記録と乱数の返送 |
| `packages/client/src/components/FairnessPanel.tsx` | 検証結果の表示 |
