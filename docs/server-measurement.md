# サーバー卓の計測と費用の仮説

2026-10-23 記録。これはローカル Miniflare の測定であり、Cloudflare の実測請求ではない。

2026-10-30 の方針変更：この記録は AWS ベースの新プロジェクトへの比較資料として残す。
以下の料金・運用検証計画は記録当時の Cloudflare 案であり、新しいAWS構成の見積もりではない。
Cloudflare の実課金検証は未完了だが、その完了を Pages検証版のタグ条件にはしない。

## 1時間の連続運転

10席の稼働卓2つと、10人接続した待機卓1つを同時に動かした。
標準ルール・初期10,000・SB10/BB20。自動クライアントは演出完了後にチェック／コールし、
各操作後に卓のチップ総数100,000を検査した。CPU の思考処理は実行していない。
測定時間は3,600,184 ms。全卓のチップ総数を維持し、操作の拒否はなかった。

| 値 | 稼働卓A | 稼働卓B | 待機卓 |
|---|---:|---:|---:|
| 開始ハンド数 | 90 | 90 | 0 |
| 保存した完了ハンド | 89 | 89 | 0 |
| 操作数 | 3,562 | 3,562 | 1 |
| alarm の実行 | 89 | 89 | 0 |
| 受信メッセージ | 3,572 | 3,572 | 11 |
| 送信メッセージ | 40,137 | 40,137 | 76 |
| 送信 JSON の総バイト数 | 506,633,677 | 506,685,038 | 604,703 |
| 状態の保存回数 | 3,682 | 3,682 | 32 |
| SQLite の使用量（バイト） | 5,185,536 | 5,189,632 | 24,576 |
| ハンド進行中の時間（ms） | 2,681,841 | 2,681,895 | 0 |
| handler の経過時間合計（ms） | 5,001 | 4,928 | 9 |

待機卓の値は参加・認証・測定時の停止操作を含む。初期化以後の定期的な進行処理はなかった。
ハンド進行中の時間は「プレイヤーを待っている時間」を含む。
handler の時間は保存完了までの全時間やプロバイダーの CPU／GB-s ではない。
状態の保存回数も alarm・履歴削除などを含む課金対象の行数とは一致しない。
自動応答の ping はアプリの受信カウンターに含まれない。

常時全員がコールする約90ハンド/時の試験で、人間の通常の利用速度や通信量を代表するものではない。
全員への合計送信量は約507 MB/卓時、1人あたり平均約51 MB/時だった。
現在は操作ごとに視点別の状態全体を送るため、実回線での検証では差分配信や履歴の別取得を検討する。
保存は直近100ハンドで打ち切る。89ハンド時点の約5.2 MBを無期限の保存量へ外挿しない。

再現コマンドは `npm run soak --workspace @wildcard/server`。
生データは `packages/server/shots-server/soak.json` に出力し、Git には含めない。
別試験で再送・再接続・Miniflare の停止／再起動・期限の保持・保存履歴を確認した。
期限後の最終ハンドの扱いは連続運転後に追加し、単体試験と通信試験で確認している。

## 月間利用量を変えた場合

まずは「クラブ数」ではなく、1卓が1時間動く **卓時間** で考える。
例えば5クラブが週1回・4時間・1卓なら、4週で80卓時間。

2026-10-23 確認時点の Workers 有料プランは月$5から。
[Workers 料金](https://developers.cloudflare.com/workers/platform/pricing/)を参照。
Durable Objects 有料枠には月100万リクエスト・400,000 GB-s・SQLite 50,000,000行の書き込み・5 GB-monthの保存が含まれる。
休止可能な待機時間は duration の課金対象外だが、実際に起きている時間は測る必要がある。
[Durable Objects 料金](https://developers.cloudflare.com/durable-objects/platform/pricing/)を参照。

下表は測定した稼働卓Aを単純に乗算した作業用の量であり、料金表の請求単位ではない。

| 月間卓時間 | 操作数 | 状態保存回数 | 全員への送信量 | 仮に稼働中ずっと128 MiBで起きていた場合の GB-s（0.125 GB換算） |
|---|---:|---:|---:|---:|
| 100 | 356,200 | 368,200 | 約50.7 GB | 45,000 |
| 500 | 1,781,000 | 1,841,000 | 約253 GB | 225,000 |
| 1,000 | 3,562,000 | 3,682,000 | 約507 GB | 450,000 |

WebSocket の受信はリクエスト課金では20メッセージを1リクエストとして扱い、alarm や接続開始は別途数える。
そのため操作数をそのまま課金リクエスト数にしない。
また有料枠の超過分には切り上げ単位があるので、含有量を少し超えた場合も単純比例で料金を計算しない。
[課金単位の説明](https://developers.cloudflare.com/durable-objects/platform/pricing/)を参照。

**月100〜500卓時間を最初の検証規模に置き、月$5の基本枠に近い費用で収まるかを確かめる**、という進め方が妥当と考える。
これは実費の保証ではない。円換算・税・認証・メール・画像・ログ・バックアップは別に確認する。
月数千円という予算を決めただけで、課金が自動停止するわけでもない。
まず限定した作成キーと5卓の上限で測り、一般公開の登録やクラブ数の拡大は測定後に行う。

## 引き継ぐ計測の観点

稼働卓数・待機卓数・卓時間と、課金対象の通信・処理・DB操作・保存量を同じ期間で記録する。
AWS版では採用するサービスの請求単位で測り、認証・フロント配信・ログ等も別に確認する。
接続復帰が多い回線、実際の操作間隔、複雑なルールを含めて比較する。
Cloudflare版を追加計測する場合は、DOのリクエスト／duration／SQLite行読み書き／保存量とWorkerのリクエスト・CPUを用いる。
この文書のローカル計測だけで、本番運用の費用検証を完了扱いにしない。

## 2026-10-24 — 公開サーバーの初回確認

Cloudflare の無料プランに配置し、ブラウザ2つ＋自動クライアント8つの10人で1ハンドを完了した。
卓の作成・招待参加・ページ再読み込みからの席と手札の復元・保存履歴・卓の終了まで確認した。
未公開カードと山札を他の席へ配信していないこと、Pages の origin が許可され、未知の origin が拒否されることも確認した。

履歴閲覧後のアプリ計測は操作42件・拒否0件、接続11回、送信611メッセージ・10,050,105バイト、
状態保存78回・履歴保存1回、SQLite 使用量143,360バイトだった。
これは単一ハンドの動作確認であり、月間利用量や請求額の測定には代わらない。
クラウド内では `Date.now()` の進み方がローカルと異なり handler 時間が0になる場合があるため、
CPU や課金時間の判断には Cloudflare 側のメトリクスを使う。
