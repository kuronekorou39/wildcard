# Wildcard — コンセプト

## 目標

**専門知識がなくても、自分たちのルールで遊べるポーカークラブを作り、招待・開催・記録の管理まで行える。**

最初の対象は、友人グループや既存コミュニティの主催者と参加者。
主催者は Wildcard 上でクラブを作り、ルールを設定して、招待リンクを共有する。
メンバーは同じクラブに戻り、繰り返し卓を囲める。

最初の完成条件は、**開発者が付き添わなくても、クラブを作って遊び、翌週また同じ場所に集まれること**。

## 合意した進め方（2026-10-23）

- Wildcard 側でオンラインの基盤を運営する。利用者にサーバーの契約・設置・保守を求めない。
- 収益化前でも月数千円程度の運営費は許容する。設計上は月3,000円程度を仮の目安に置く。
- この金額はサービス全体の見積もりや請求上限の保証ではない。小規模で実測して運営可能な範囲を決める。
- サーバーで進む卓を検証し、最小限のクラブ機能をつなぎ、少数のクラブで継続利用を確認する。
- 現在の GitHub Pages は、ルール・画面・進行の挙動を確認するプレビューとして活かす。

具体的な開発順序と完了条件は [roadmap.md](./roadmap.md) にまとめる。
クラウド事業者、認証方式、料金プランはまだ決めていない。

## 中心となる価値 — 自分たちのルールで開催できること

Wildcard は**ルール定義を入力データとして受け取る**。
標準ルールから始め、必要なところだけ変更してクラブに保存できる体験を目指す。

- スートやランクの構成、カードの強さ順
- 手札や盤面の枚数、役に使うカードの制約
- 標準役の有効・無効と優先順位
- カスタム役の条件（例: `X, X, Y, Y+1, Y+2`）
- 賭け方や卓の作法

現在表現できる範囲は [variants.md](./variants.md) に記す。
あらゆるポーカー種目を実装済みという意味ではない。
このルール設定と、クラブの開催・記録を一続きの体験にする。

## 最初のクラブ版の範囲

| 要素 | 目指す形 |
|---|---|
| アカウント | Wildcard 共通。一人が複数クラブに所属できる |
| クラブ | メンバー、管理者、保存したルール、開催記録を持つ |
| 招待 | リンクを共有し、クラブへの参加と卓への着席につなげる |
| テーブル | 必要なときに開催。最大10人。主催者の端末に依存せず進行する |
| 見た目 | クラブ名・アイコン・バナーを設定できる |
| チップ | クラブ内で管理し、付与・増減の記録を残す。持ち越しの扱いは仕様を詰める |
| 記録 | 結果、アクションの手順、盤面、チップの動きを確認できる |

## 配信と運営

### 現在のプレビュー

GitHub Pages に静的配信している。ソロとホットシートはブラウザ内で動き、
オンライン対戦は WebRTC による一時的な P2P 卓として動く。
接続には外部の公開トラッカー等を利用する。アカウントやクラブの継続保存はない。

P2P では進行役の端末がゲームの全状態を持つ。この前提と検証の仕組みは
[fairness.md](./fairness.md) に記す。クラブ版のサーバー運営とは区別する。

サーバーで進行・保存する10人卓を実装し、Cloudflare に検証環境を配置した。
現在の試作の席はブラウザ内の接続情報で識別し、
アカウントやクラブの所属による認証は次の段階で加える。

### これから作るクラブ版

クラブ・メンバー・ルール・記録は保存し、卓の進行はサーバーが管理する。
複数クラブで基盤を共有し、クラブごとに専用サーバーを常時確保する構成は前提にしない。
画面の描画、音、アニメーションはブラウザで動かす。

費用は同時に動く卓、処理量、保存量などを測って判断する。
招待制の少数クラブから始め、同時卓数・保存期間・使用量の通知を設計する。
保守や問い合わせにかかる時間も、継続できるかを判断する材料にする。

将来は主催者向けの月額プランを候補とする。
同時卓数、長期の履歴保存、イベント管理などの価値と運営費を確認してから価格を決める。
参加者が入りやすいことを重視する。

## 画面と操作の方針

- ゲーム中は画面全体のスクロールを必要としない。設定も画面内の操作を基本とし、長い一覧だけを内部でスクロールする。
- 通常は値を読みやすく表示し、変更するときに入力欄へ切り替える。
- スマホでは自分の手札と操作領域を確保し、大画面では盤面・文字・操作部を適切に拡大する。
- ゲーム画面は現在の仕上がりを基準にし、クラブへの接続で必要になる表示や不具合を優先して直す。

## 初期の対象外

- リアルマネー、換金、賭博性のある運用
- 不特定多数の自動マッチメイキング、全体ランキング、公開クラブの検索・募集機能
- 大規模同時接続、複数卓トーナメント、複雑なイベント管理
- 利用者自身のクラウドへの設置版、専用サーバーの提供
- 料金徴収の実装と有料プランの確定
